# DSH RTL — راست‌چین‌ساز DeepSeek Harness

[🇬🇧 English](README.en.md) · **فارسی**

افزونهٔ کروم (Manifest V3) که رابط وب **DeepSeek Harness** را راست‌به‌چپ می‌کند و فونت
**وزیرمتن** را روی آن می‌نشاند — بدون دست‌زدن به کد DSH و بدون ریسک از دست رفتن
تغییرات بعد از هر به‌روزرسانی.

سه حالت دارد و با یک کلیک عوض می‌شود:

- **کامل** — کل رابط می‌چرخد.
- **فقط چت** — تنها متن گفتگو راست‌چین می‌شود؛ سایدبار، هدر، تب‌ها، کمپوزر و بقیهٔ
  اجزای هارنس دقیقاً دیفالت خودشان می‌مانند.
- **خاموش** — هیچ تغییری.

در هر حالت، کد، ترمینال، دیف، درخت JSON، مسیر فایل و فرمول ریاضی **چپ‌به‌راست**
می‌مانند تا خواندنشان خراب نشود.

![پاپ‌آپ DSH RTL](docs/popup.png)

## ۱) نصب

1. کروم را باز کنید و به `chrome://extensions` بروید.
2. کلید **Developer mode** (حالت توسعه‌دهنده) را در گوشهٔ بالا-راست روشن کنید.
3. روی **Load unpacked** بزنید و پوشهٔ همین پروژه (`RTL-Ai`) را انتخاب کنید.
4. رابط DSH را باز کنید: `http://127.0.0.1:3080` — یا یک‌بار صفحه را نوسازی کنید.

> افزونه به‌طور خودکار روی `127.0.0.1` و `localhost` فعال می‌شود، اما فقط اگر
> تشخیص بدهد که صفحه واقعاً DSH است (عنوان صفحه، `manifest.webmanifest`،
> `favicon.svg` یا `window.__DSH_BOOT__`).

برای دامنه‌های دیگر (مثلاً DSH روی یک سرور LAN): پاپ‌آپ افزونه → بخش «این صفحه» →
**همیشه فعال** را انتخاب کنید؛ کروم مجوز همان دامنه را می‌پرسد.

## ۲) سناریوهایی که پیاده‌سازی شده

| سناریو | رفتار |
| --- | --- |
| **سه حالت نمایش** | **کامل** (کل رابط)، **فقط چت** (تنها محتوای گفتگو)، **خاموش** (هیچ تغییری) |
| **حالت «فقط چت»** | نه `dir` روی `<html>` و نه هیچ قاعده‌ای روی پوسته؛ فقط حباب پیام کاربر و مارک‌داون پاسخ راست‌چین می‌شوند و سایدبار/هدر/کمپوزر دیفالت هارنس می‌مانند |
| **چرخش کل رابط** | `dir="rtl"` روی `<html>` → سایدبار به راست، کمپوزر و تب‌ها آینه، نوار اسکرول به چپ |
| **فونت فارسی** | بازنویسی توکن‌های رسمی تم (`--dsw-font-family`) → همهٔ کامپوننت‌ها با وزیرمتن |
| **جهت هوشمند پاراگراف** | هر پاراگراف بر اساس اولین حرف قوی‌اش جهت می‌گیرد: فارسی راست، انگلیسی چپ |
| **جزیره‌های چپ‌به‌راست** | `pre/code/kbd`، بلوک کد، ترمینال، دیف، نتیجهٔ Read/Search، درخت JSON، مسیر فایل، KaTeX |
| **کمپوزر (ویرایشگر Lexical)** | جهت با CSS اعمال می‌شود (نه با `dir`) تا Lexical آن را بازنویسی نکند؛ هر خط کد داخل متن هم چپ می‌ماند |
| **دکمه‌ها و منوها** | `text-align:left`های پراکندهٔ اپ به `start` تبدیل می‌شود؛ زیرمنو و منوی کشویی به لبهٔ درست می‌چسبد |
| **مارک‌داون** | بولت لیست، نقل‌قول، جدول و چک‌باکس تسک‌لیست آینه می‌شوند |
| **آینه‌کردن آیکون‌ها** | شورون دیسکلوزر، کرت تب و دستهٔ پنجرهٔ شناور — با `scale` تا با `rotate` داخلی اپ تضاد پیدا نکند |
| **داک و پنجرهٔ شناور** | ناحیه‌های رهاکردن پنل، دکمهٔ بستن تب و دستهٔ تغییر اندازه به سمت درست منتقل می‌شوند |
| **تبدیل ارقام** | اختیاری: `123` → `۱۲۳` فقط در متن گفتگو؛ کد، URL، نسخه‌ها و مسیرها مستثنا |
| **دکمهٔ شناور + میان‌بر** | قرص کوچک قابل‌جابه‌جایی با سه حالت رنگی و `Alt + Shift + R` برای چرخهٔ حالت‌ها |

### حالت‌ها دقیقاً چه می‌کنند؟

| حالت | `<html>` | پوستهٔ هارنس | محتوای گفتگو |
| --- | --- | --- | --- |
| **کامل** | `data-dsh-rtl="full"` + `dir="rtl"` | راست‌چین می‌شود | راست‌چین می‌شود |
| **فقط چت** | `data-dsh-rtl="chat"` (بدون `dir`) | **دست‌نخورده** | راست‌چین می‌شود |
| **خاموش** | هیچ اتریبیوتی | دست‌نخورده | دست‌نخورده |

این جداسازی با **دو دروازهٔ جدا** در CSS انجام می‌شود:

```css
/* پوسته: فقط در حالت کامل */
html[data-dsh-rtl="full"][dir="rtl"] { … }

/* محتوا: در هر دو حالت */
html[data-dsh-rtl][data-dsh-rtl-chat="on"] { … }
```

## ۳) چرا این‌طور کار می‌کند

سه چیز در DSH از بررسی نسخهٔ نصب‌شده (`dsh-web-frontend` و بسته‌های
`dsh-client-ui-*`) پیدا شد و پایهٔ طراحی افزونه شد:

1. **اپ هیچ پشتیبانی RTL ندارد.** نه `dir` می‌گذارد، نه `[dir=rtl]` در CSS دارد؛
   پس افزونه باید واقعاً چیدمان را بچرخاند.
2. **فونت‌ها از طریق CSS Variables می‌آیند.** پلاگین `dsh-client-ui-theme`
   مقادیر `--dsw-font-family` و `--ds-font-family-code` را روی `:root` تعریف
   می‌کند و همهٔ ماژول‌ها از آن ارث می‌برند. پس فقط دو متغیر بازنویسی می‌شود،
   نه صدها سلکتور.
3. **اپ نقاط اتصال معنایی دارد.** اتریبیوت‌هایی مثل `data-terminal`، `data-diff`،
   `data-code-block-content`، `data-read`، `data-search`، `data-json-root-row`،
   `data-composer-input`، `data-lexical-editor` و `data-dockkit-*` دقیقاً همان
   چیزهایی هستند که برای جدا کردن «کد» از «متن» لازم است.

نکتهٔ فنی مهم: کلاس‌های اپ **CSS-Module با هش بیلد** هستند
(`._markdown_kcgor_5`)؛ هش با هر بیلد عوض می‌شود ولی **نام معنایی** می‌ماند.
به همین دلیل سلکتورها با `[class*="_markdown_"]` نوشته شده‌اند، نه با هش کامل.

دروازهٔ CSS:

```css
html[data-dsh-rtl="on"][dir="rtl"] { … }
```

specificity این سلکتور `(0,2,1)` است؛ یک پله بالاتر از قواعد اپ (`(0,1,1)` و
`(0,2,0)`)، پس بدون `!important` برنده می‌شود. خاموش‌کردن افزونه فقط برداشتن
همین دو اتریبیوت است، پس هیچ پرش یا دوباره‌رندر شدنی رخ نمی‌دهد.

## ۴) تنظیمات

پاپ‌آپ افزونه (کلیک روی آیکون):

- **کلید اصلی** روشن/خاموش در هدر
- **حالت نمایش**: کنترل سه‌قسمتی «کامل / فقط چت / خاموش» با نشانگر لغزان
- **دامنهٔ اثر روی این سایت**: خودکار / همیشه / هرگز
- **قلم**: انتخاب خانوادهٔ فونت به‌همراه **پیش‌نمایش زندهٔ متن فارسی**، و فاصلهٔ خطوط
- **رفتار**: جهت هوشمند پاراگراف، کد و ترمینال چپ‌به‌راست، آینه‌کردن آیکون‌ها
  (در حالت «فقط چت» خودکار بی‌اثر و کم‌رنگ می‌شود)، تبدیل ارقام، دکمهٔ شناور
- **تنظیمات پیشرفته**: انتخابگرهای اضافی برای LTR نگه‌داشتن + CSS سفارشی + تشخیص خودکار DSH

### دو راه فرار برای موارد خاص

- **انتخابگرهای LTR**: هر سلکتوری که بنویسید به فهرست «جزیره‌های چپ‌به‌راست»
  اضافه می‌شود. مثال: `[data-testid="my-widget"]`
- **CSS سفارشی**: هر قاعدهٔ دلخواه، مستقیم روی صفحه تزریق می‌شود. مثال:

```css
html[dir="rtl"] .something { margin-inline-start: 12px; }
```

تنظیمات در `chrome.storage.sync` ذخیره می‌شود؛ تغییرات **بدون نوسازی صفحه** و
بلافاصله روی همهٔ تب‌های باز DSH اعمال می‌شوند.

## ۶) رفع اشکال

| نشانه | علت / راه‌حل |
| --- | --- |
| می‌خواهم فقط متن چت راست‌چین شود و بقیه دیفالت بماند | حالت **«فقط چت»** را از پاپ‌آپ یا با `Alt+Shift+R` انتخاب کنید |
| حالت «خاموش» انتخاب می‌کنم ولی چیزی عوض نمی‌شود | اگر «همیشه» روی این سایت انتخاب شده باشد، حالت انتخابی اعمال می‌شود؛ «دامنهٔ اثر» را روی «خودکار» بگذارید |
| پاپ‌آپ می‌گوید «DSH نیست» | صفحه DSH نیست، یا `detectOnly` روشن است و نشانه‌ای پیدا نشد؛ «همیشه» را بزنید |
| پاپ‌آپ می‌گوید «اجرا نشده» | افزونه بعد از باز شدن صفحه نصب/فعال شده؛ صفحه را نوسازی کنید یا «اعمال فوری» بزنید |
| فونت عوض نشد | یک بار صفحه را نوسازی کنید (`@font-face` در منابع افزونه است و باید در دسترس قرار گیرد) |
| جایی از رابط چپ ماند | آن سلکتور را در «انتخابگرهای LTR» یا موقتاً از حالت «جهت هوشمند» خارج کنید |
| بخشی از یک کامپوننت جدید به‌هم ریخت | در «تنظیمات پیشرفته» با CSS سفارشی اصلاح کنید و همان سلکتور را در «انتخابگرهای LTR» بگذارید |
| دکمهٔ شناور مزاحم است | در پاپ‌آپ خاموشش کنید |

## ۸) تست‌ها

قواعد RTL در برابر قواعد واقعی اپ شکننده‌اند (specificity، ویژگی‌های فیزیکی،
متغیرهای CSS). برای همین سه لایه تست خودکار در مرورگر واقعی وجود دارد:

```powershell
pwsh -File test/run-tests.ps1
```

| تست | چه چیزی را می‌سنجد |
| --- | --- |
| `test/selftest.html` | یک DOM شبیه‌سازِ DSH می‌سازد، **قواعد خود اپ را بعد از شیت افزونه** تزریق می‌کند (بدترین حالت cascade) و **۷۲ چیز** را در سه حالت می‌سنجد: بارگذاری واقعی فونت، جزیره‌های چپ‌به‌راست، آینه‌شدن مارک‌داون، flipped شدن ویژگی‌های فیزیکی، آینه‌نشدن آیکون ابزارها، دست‌نخوردن پوسته در حالت «فقط چت» و برگشتن کامل صفحه به حالت اول در حالت «خاموش» |
| `test/popup-probe.html` | **۲۱ سنجهٔ** چیدمان پاپ‌آپ: عرض ثابت ۳۸۴px، نبود سرریز افقی، بریده‌نشدن برچسب‌ها، RTL بودن، LTR ماندن تکست‌اریای CSS، پیش‌نمایش فونت و کنترل‌های سه‌قسمتی |
| `test/e2e.js` | **خودِ افزونه را در کروم بارگذاری می‌کند** (CDP) و **۴۳ سنجه در سه فاز** می‌گیرد: فاز A حالت کامل، فاز B حالت «فقط چت» (پوسته باید دست‌نخورده بماند)، فاز C حالت خاموش. شامل لود و رندر واقعی `woff2` از `chrome-extension://` و پاک‌سازی کش بین فازها |

خروجی فعلی روی Chrome 152: `PASS=72 FAIL=0`، `PASS=21 FAIL=0`، E2E → `ALL-PASS (43 checks)`
— جمعاً **۱۳۶ سنجه**.

> نکتهٔ کروم ۱۳۷+ : سوئیچ `--load-extension` از کروم رسمی حذف شده
> ([Selenium](https://github.com/SeleniumHQ/selenium/issues/15788)،
> [uBOL](https://github.com/uBlockOrigin/uBOL-home/discussions/342)). تست E2E
> به‌جای آن از دامنهٔ `Extensions` در DevTools Protocol استفاده می‌کند
> (`--enable-unsafe-extension-debugging` + `Extensions.loadUnpacked`) و تنظیمات
> هر فاز را از صفحهٔ خود افزونه در `chrome.storage.sync` می‌نویسد.
> اگر مرورگر اجازهٔ بارگذاری ندهد، اسکریپت با کد ۳ خارج می‌شود و دو تست دیگر
> همچنان معتبرند.

## ۹) نکته‌ها

- **مجوزها کمینه است**: `storage` برای تنظیمات، `scripting` برای پشتیبانی از
  دامنه‌های دلخواه، `activeTab` برای خواندن نشانی تب جاری. دسترسی به دامنه‌های
  غیرلوکال فقط با تأیید صریح خودتان (`optional_host_permissions`) گرفته می‌شود.
- **حریم خصوصی**: هیچ داده‌ای جایی فرستاده نمی‌شود؛ افزونه کاملاً محلی کار می‌کند.
- **فونت**: [Vazirmatn](https://github.com/rastikerdar/vazirmatn) اثر صابر راستی‌کردار،
  با مجوز SIL Open Font License 1.1 همراه افزونه توزیع شده است؛ متن مجوز در
  [`fonts/LICENSE-Vazirmatn.txt`](fonts/LICENSE-Vazirmatn.txt) قرار دارد.
- **بدون پرش (flash)**: خواندن تنظیمات از `chrome.storage` غیرهمگام است؛ افزونه
  تا رسیدن پاسخ **هیچ‌چیز اعمال نمی‌کند** (مگر کش همگام `localStorage` موجود باشد).
  بدون این محافظ، صفحه یک لحظه حالت پیش‌فرض را می‌گرفت و بعد اصلاح می‌شد.
- **`unicode-bidi` ارثی نیست**: برای «جهت هوشمند پاراگراف» باید علاوه بر ظرف
  مارک‌داون، خودِ `p/li/td/...` هم علامت بخورند؛ وگرنه فقط متن حباب جهت هوشمند
  می‌گیرد و پاراگراف‌های تودرتو نه.
- **سازگاری**: اگر روزی DSH نام‌های CSS-Module را عوض کند، افزونه نمی‌شکند بلکه
  فقط بخشی از تعمیرهای ظاهری بی‌اثر می‌شود؛ ستون اصلی (جهت + فونت + جزیره‌های کد)
  بر پایهٔ اتریبیوت‌های `data-*` است که پایدارترند.
- **مجوز**: کد زیر [MIT](LICENSE) است؛ فونت‌های همراهِ افزونه همچنان زیر
  SIL OFL 1.1 می‌مانند (بند بالا).
- اگر ترجیح می‌دهید این کار به‌جای افزونهٔ کروم، یک **پلاگین خود DSH** باشد
  (بسته‌های `dsh-client-ui-*` با CSS سرخود)، بگویید تا همان را هم بسازم؛ مزیتش
  نبود کروم و کار کردن روی همهٔ کلاینت‌هاست، عیبش نیاز به نصب در محیط DSH.
